知间：中文 AI 知识卡 Demo 与 footprint 实施计划白皮书

版本：0.1 候选审阅稿 · 2026-10-21 · 为 Cypher 编写

本文记录已对齐的产品原则、20 张真实样本和下一阶段实施门槛。本 Demo 已独立制作，但不代表生产架构、内容协议或 footprint 接入已获批准。所有卡片个人认同均为“待认同”。

1. 交付目的与阅读路径

Cypher 已具备 React / TypeScript 工程经验，计划转向 AI 工程。项目最终落地点是 footprint，KnowledgeBlocks 提供“内容可组合、语义与呈现分离”的思路。本轮先用足够真实的内容和交互，检验知识卡是否值得长期阅读，再根据审阅结果讨论协议。

建议先打开 index.html：自由浏览 20 张卡，或选择“厘清概念”“理解循环”“可靠执行”。优先阅读 State vs Context、Agent Loop、Checkpoint 与 Structured Output vs Business Validation，分别检验关系对照、反馈流程、边界解释和代码场景。再沿关联进入其他卡，返回时检查是否回到刚才的阅读位置。默认阅读；需要时才打开复习并揭示参考答案。

白皮书不是只有目录或摘要。第 2 节记录对齐结果，第 4–7 节说明内容与候选结构，第 8–12 节提供后续生产实施计划，附录保留真实来源与审查方法。完整的 20 张正文另存于 cards.json；H5 内嵌同一内容，无需联网取数。

3. 目标、非目标与权限边界

本轮目标是：制作精致且可靠的 20 卡 H5、展示多类型和多组合、提供可审查证据及完整实施计划、交付易于保存和转发的离线文件。用户电脑离线，所以使用已保存的 KnowledgeBlocks 云工作区独立演示。

本轮非目标包括：接入 footprint 生产代码、导入或覆盖现有知识、建立新数据库、引入大框架、冻结 schema、搭建自动布局系统、运行真实 Agent、训练或调用模型、自动产生用户认同、merge、push、公开或私有部署。没有增加重大依赖；H5 运行不依赖第三方 JS、CSS、字体、CDN 或网络接口。

工作目录为 /workspace/ai-knowledge-demo-20261021。KnowledgeBlocks 仓库仅只读检查；已看到的版本为 d3d5443701ccf4c44f0d0c5b03232fe57b2abe1f。本轮不创建收费并行任务，不自行切换模型；遵守用户选择的 6.1 Sol high 执行范围。没有模型 API 调用，因此不虚构 token 成本估算。若后续需要外部服务、部署、付费生成或新增重大依赖，应单独说明具体范围与成本后再获得相应授权。

5. 内容制作与来源核验标准

每卡先写一句学习目标，再写概览。概览应直接回答核心问题，并保留对结论成立至关重要的限制，不能只写“本文将介绍”。正文补足理解所需解释，随后使用有区分力的例子、反例、代码或流程。删掉不会改变读者认知的重复描述，不用同义改写填满格子。

本轮来源优先官方文档与原始论文，核对日期为 2026-10-21。每个 sources 条目包含可打开链接、支持范围、来源性质和核对日期。来源支持只覆盖所写范围；中文总结、对比维度、场景和工程建议属于作者综合，不冒充官方原句。没有编造逐字引文，没有复制文档大段正文。论文性能数字没有移植到本 Demo，也未声称重现实验。

关键核验要求：

  1. State 是应用维护数据，可能有错误、猜测和 unknown；它不天然持久化，也不天然是事实。
  2. Context 不是严格的 State 子集。静态指令、即时检索和服务端机制可能独立于应用保存的数据；还要区分窗口容量与实际输入。
  3. Checkpoint 恢复应用状态，不自动回滚工单、邮件等外部效果；恢复或重放时需检查副作用与代码版本。
  4. 超时表示未及时收到响应，不能证明未执行。保留未知，先对账或查回执，再按服务合同重试。
  5. schema 合格不等于对象存在、权限有效或业务状态允许；生成约束也需处理拒答、截断和所支持 schema 的范围。
  6. 客户端工具由应用执行并回传结果；服务端工具由厂商执行。不能把一个客户端工具循环当成所有工具执行方式。
  7. 向量相似不等于事实正确；不同 embedding 空间不能随意混用。本文不给未测过的相似度分数。
  8. 检索找候选、重排排候选；遗漏在候选集之外的证据通常不能靠重排找回来。
  9. LangGraph 的 state、checkpoint、interrupt 细节标明是框架约定，不包装成全行业规范。
  10. MCP 解决协议互通，不自动完成 Agent 的模型决策、授权、记忆或业务校验。

核验记录应能回答“哪一个页面的哪一部分支持哪条核心判断”。本轮 evidence/SOURCE_AUDIT.md 保留实际 URL、章节定位与支持范围；逐卡更细的范围位于 cards.json。未来如来源失效，保留原地址、最后核对日期与待复核状态，不悄悄换成一篇无关页面。

已发现的版本变化：Anthropic 两篇工程文章从 engineering 路径重定向到 research；MCP 架构页落到 2026-07-28 版本；旧 LangGraph durable-execution 路径目前重定向到 Persistence，不能继续把该旧 URL 视作完整 durable execution 指南。本 Demo 改用当前 Checkpointers 与 Interrupts 页面核对恢复边界。

人工审核顺序：先核查核心断言及紧邻限定，再看解释能否支撑例子，最后看关联和复习问题是否仍围绕同一目标。可标注“来源支持”“作者综合”“工程建议”“待复核”；这些是证据标签，不是替用户认同的等级。

7. 统一外壳、block 与交互规则

视觉基线：白色纸面、暖灰背景、深灰绿色正文、柔和绿 #42b983 标记关联与强调。英文主题用衬线建立阅读层级，正文使用系统中文无衬线字体。高密度信息依靠留白、线条、字级、段落节奏区分，不使用整屏强渐变和夸张的大标题。

同类 block 使用固定样式：文字为连续段落；对比为带表头的数据表；流程为编号步骤并明确循环或出口；例子有轻背景与“例”标记；代码使用等宽暗底、可横向滚动并可复制；提示使用暖色边界块。流程不是执行器，代码只渲染不运行。每张卡只调整内容与块次序，没有逐卡布局参数。

布局响应视口改变：桌面目录为多列，并对首张精选做编辑式展示；移动目录为单列。完整阅读桌面保留局部目录与返回，移动优先正文宽度。对比表保持语义；代码溢出限制在代码框内部，不把整页撑宽。不同组合不是随机排版；任何布局都不得改变作者 block 顺序或删去关键限定。

8. 手工知识链接与个人认同

关联由作者选择，当前只做卡级跳转，不建立段落依赖图。挑选关联时应能解释它解决了读者的哪一个后续问题。例如 Checkpoint 关联 Idempotency，是为了理解恢复为什么可能重复外部效果；State vs Context 关联 Context Builder，是为了理解两类信息之间如何装配。

生产阶段可以给关联加简短说明，但不应因此恢复复杂 role/target 挂载。失效链接必须在内容检查时暴露。允许单向关联；是否需要双向反链、关系名和正文内锚点由阅读反馈决定。浏览历史只是临时 UI 状态，不当成内容依赖。

个人认同独立于来源。所有 20 张保持待认同；当前 Demo 没有“自动已认同”动作，也不保存用户身份或学习记录。正式认同至少应绑定用户、内容版本、态度与时间；正文大改后如何提示重新审阅，需要用户决定。它不是“官方正确”的投票，也不是来源审核的替代品。

9. 未来 AI 草稿流程

AI 的位置是构建期起草，不进入阅读时的实时内容生成。先选定学习目标与原始资料，再由 AI 提供带来源位置的草稿；人工逐条核查并修改，确认后才进入可阅读卡库。不能直接把 footprint 既有 AI 内容当权威或批量认同。

候选流程：

  1. 编辑建立选题、受众、中心问题、来源候选和明确边界。
  2. 取回原文，记录 URL、日期、章节或稳定定位；找不到原文就标待补证据。
  3. AI 输出候选概览、blocks、来源支持映射、待确认问题与手工关联建议。
  4. 人工先核事实，再改表达与次序，明确原创例子、工程建议和框架限定。
  5. 执行结构及关联检查，并在桌面/移动阅读视图检查正文、预览和复习。
  6. 人工确认可入库；个人认同仍由 Cypher 明确选择，不由编辑或 AI 代填。

草稿版本和已确认版本应可区分。需要模型服务时，先说明模型、单次或批量范围、预算与失败处理；本轮不提前批准该未来收费流程。没有必要为了起草先建设多 Agent 系统。
