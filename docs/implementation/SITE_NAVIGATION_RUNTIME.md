## Article outline hierarchy (2026-10-10)

The reading rail now builds an ordered forest from mounted H2–H6 headings. Each heading belongs to its nearest preceding lower-numbered heading; skipped levels do not synthesize sections, and H1 remains the article title. Root entries alone receive numbers. Nested semantic `ul` lists, independent 44px disclosure buttons, `aria-controls` and `aria-expanded` provide the expanded outline; the compact desktop/mobile rail shows only forest roots. Author Markdown and all heading IDs are unchanged.

Only the precise heading has `aria-current=location`; its ancestors use a separate path class, including the visible root in compact mode. Scroll changes reveal the current path without closing other branches. A manual disclosure choice suppresses automatic reopening for that branch until an explicit deep-anchor jump reveals the path. Ordinary same-article anchor changes preserve the rail DOM and keyboard focus; route/content/mode changes clean up observers/listeners and rebuild. Directory scrolling changes only its own scrollTop. Ordinary heading positioning and tracking use Docute's existing 80px anchor offset.

`test:toc` checks the actual DOM article (8 roots versus 126 headings), exact nodeName positioning and H2/H3/H4 ancestry, compact root navigation, current/ancestor state, manual branches, keyboard controls, independent long-directory scrolling, reload/back and 320/390/768/1440 layouts. Intercepted Markdown fixtures cover complete H2–H6 nesting, skipped levels, no H2, single-level and empty outlines, and duplicate labels with distinct IDs. Shared outline assertions now verify real list ancestry and root numbering in the reading and site-navigation regressions, including modes, complete view and canonical routes. Evidence is local and ignored. Chrome is tested; physical devices, Safari/Firefox and native screen-reader speech are not.
