# 函数式编程：纯计算、组合与副作用边界

> 审阅日期：2026-10-08。状态：概念整理；示例未执行。

## 1. 核心概念

| 概念 | 含义 |
| --- | --- |
| 纯函数 | 给定相同输入，得到相同结果且不产生外部副作用 |
| 高阶函数 | 接收或返回函数 |
| 不可变更新 | 生成新值而不修改原数据 |
| 组合 | 把小变换连接成更大的变换 |
| 副作用边界 | 把 I/O、时间和随机性从纯计算中显式隔离 |

函数式与面向对象可以组合使用。旧文把语言历史分成“实用”和“不实用”两派，属于观点化概括，不作为事实基础。

## 2. 最小例子

```js
const selectVisible = cards => cards.filter(card => !card.hidden);
const titles = cards => cards.map(card => card.title);
const visibleTitles = cards => titles(selectVisible(cards));
```

这些函数假定输入结构合法。返回新数组不意味着嵌套对象也已深复制。

## 3. 工程价值与代价

纯核心便于单元测试和回放；过多中间数组、过深组合或晦涩抽象也可能增加成本。目标是清晰的输入输出，不是把所有循环强行写成 reduce。

## 4. AI 时代的应用

把“模型输出 → 校验 → 状态转换”做成可单独检查的步骤，把外部工具执行放在受控边界。确定性函数能验证局部性质，但不能消除模型与网络的不确定性。

## 5. 练习

将一个读取当前时间并写日志的价格计算函数拆成纯计算与副作用。再说明测试时怎样提供时间输入，而不是修改全局环境。
