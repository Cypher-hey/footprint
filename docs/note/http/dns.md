# DNS：查询、缓存与传输协议

> 核查日期：2026-10-08。状态：正文纠错与协议资料核查，未抓包实测。

## 1. 核心概念

DNS 保存分布式命名信息。A/AAAA 可把名称映射到 IP，CNAME 表达别名，其他记录可表达邮件路由等信息；它不只是单一的域名转 IP 函数。

## 2. 递归与迭代

终端通常把问题交给递归解析器，由它完成后续查询。解析器在缓存未命中时，可以向根、顶级域和权威服务器迭代取得转介或答案。

迭代指询问方根据转介继续查询，不等于人类用户手动发很多请求。解析并非“向上找，直到根服务器替所有域给出 IP”。

## 3. 缓存

记录 TTL 限制缓存有效时间，不保证更改后全球立即一致。终端、系统和递归解析器可能分别缓存；还存在负响应缓存。hosts、浏览器 DNS、安全 DNS 与系统解析之间的优先关系不能写成所有系统相同的固定链。

## 4. UDP、TCP 与加密传输

传统 DNS 常使用 UDP/TCP 53。旧文总结写“43”是错误。DNS 不是只支持 UDP，完整实现需支持 TCP；大响应、截断重试等场景尤其相关。DoT、DoH 则引入不同的加密传输方式。

## 5. 负载分配的边界

返回多个地址、地域调度等可帮助流量分配，但客户端选择、缓存和连接复用会影响结果。DNS 轮询不保证每台服务器负载完全均匀，也不等同于具备实时健康检查的应用层负载均衡。

## 6. 排查与练习

分别检查解析结果、TTL、实际连接地址、TLS 和 HTTP 状态。能解析到地址不代表服务可用。练习：修改记录后某些用户仍访问旧服务器，列出缓存和长连接等可能原因。
