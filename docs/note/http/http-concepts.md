# HTTP 基础：语义、版本、连接与状态码

> 核查日期：2026-10-08。状态：正文纠错、规范对照；报文与网络行为未实测。

## 1. 语义与传输分开理解

HTTP 是应用层协议。请求/响应、方法、状态码和字段表达交互语义；不同版本可采用不同的消息编码与传输机制。

| 版本 | 传输与编码的常见特征 | 不应误解为 |
| --- | --- | --- |
| HTTP/1.1 | TCP、文本头部、连接复用 | 一请求一断连 |
| HTTP/2 | 二进制帧、多路复用 | 所有队头阻塞都消失 |
| HTTP/3 | QUIC、多流 | 不需要可靠传输或安全机制 |

“二进制”不等于加密；HTTPS 与明文 HTTP 的区别也不能用是否文本编码解释。

## 2. 无状态与应用会话

无状态不是服务器禁止保存数据，也不是连接必须断开。应用可以通过 Cookie、令牌和服务端会话关联请求。连接复用和登录态属于不同层。

## 3. 方法

GET/HEAD 用于读取语义；POST 请求处理提交内容；PUT 通常表达目标表示的替换；DELETE 请求移除目标关联。具体行为必须由接口合同定义。

没有“GET 统一 2 KB、POST 默认 8 MB”的通用协议规则。Cookie 也不专属于 GET。详见 [GET 与 POST](get-post.md)。

## 4. 常见状态

| 状态 | 语义要点 | 排查方向 |
| --- | --- | --- |
| 200 | 请求成功 | 仍需验证业务内容 |
| 204 | 成功且无响应内容 | 不应强行 JSON.parse |
| 304 | 条件请求可复用缓存表示 | 检查验证器与缓存 |
| 401 | 缺少有效认证 | 检查认证挑战与凭据 |
| 403 | 拒绝执行 | 检查授权，不盲目重试 |
| 404 | 未找到或不愿披露 | 检查对象与路径 |
| 405 | 目标不支持该方法 | 检查 Allow 字段 |
| 429 | 请求过多 | 遵循服务策略和退避 |
| 502 | 网关收到无效上游响应 | 检查上游和代理链 |
| 503 | 暂不可用 | 容量、维护和重试策略 |

Access-Control-Allow-Methods 是 CORS 字段，不等同于 405 的 Allow。HTTP 200 也不能证明业务目标完成。

## 5. 重定向

301/302 对 POST 的改为 GET 存在规范允许的历史兼容行为；303 指向供检索的另一资源；307/308 保持方法。不能把所有 3xx 理解成完全相同的“重新 GET”。

## 6. 验证练习

一次 POST 返回 302 后，浏览器第二次发什么方法？如果必须保持方法应使用什么语义？一次 502 能否证明源服务器没有执行写操作？结合真实报文解释。
