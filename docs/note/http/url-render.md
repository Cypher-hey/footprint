# 从 URL 到页面：导航、网络与渲染的交叠过程

> 核查日期：2026-10-08。状态：概念审阅；未采集真实导航轨迹。

## 1. 这不是固定串行流水线

浏览器可能复用连接、命中缓存、由 Service Worker 响应、发生重定向，或从往返缓存恢复。以下是一次典型网络导航的教学模型，不是每次访问都执行全部步骤。

## 2. 主要阶段

1. 解析 URL、确定源与导航策略；HTTP 默认端口 80，HTTPS 默认 443。
2. 检查缓存及拦截路径，必要时解析 DNS。
3. 建立或复用连接，完成必要的安全握手。
4. 发送请求，服务端处理并返回状态、头和正文。
5. 增量解析 HTML，发现子资源；样式、脚本和图片可能并行下载。
6. 样式计算、布局、绘制与合成；脚本和后续资源继续更新页面。

## 3. 协议差异

HTTP/1.1 和 HTTP/2 常运行在 TCP 上；HTTP/3 使用 QUIC。不能把 TCP 三次握手画成所有 HTTP 请求的必经步骤。HTTPS 的认证与加密也不能从流程图里省略。

## 4. 页面什么时候“完成”

DOMContentLoaded、load、首屏可见、最大内容绘制和可交互不是同一时刻。异步数据、懒加载和流式界面可能在 load 之后继续变化。用业务目标定义可用，而不是只观察一个事件。

## 5. 验证方法

结合 Network 瀑布、Performance 轨迹和业务埋点，区分等待响应、资源下载、脚本执行和渲染成本。重复访问与首次访问分别测；禁用缓存会改变真实路径。

练习：为什么第二次访问可能不经历新的 DNS 或连接建立？为什么 HTML 返回很快，页面仍不能操作？
