# Nginx：反向代理、负载均衡与配置边界

> 核查日期：2026-10-08。状态：官方资料与旧示例审阅；没有修改配置、启动或重载服务。

## 1. 正向与反向代理

正向代理代表客户端访问目标；反向代理作为服务入口把请求转给后端。反向代理不要求后端绝对无法直接访问，是否隔离由网络与访问策略决定。

## 2. 负载均衡

轮询、权重、最少连接和哈希等策略解决不同问题。它们不是简单“随机分配”；ip_hash 也不能保证解决所有会话一致性问题，客户端 IP 变化、故障迁移和共享出口都影响效果。

健康检查分被动与主动，具体功能取决于版本和发行形态，不能把所有高级策略写成默认可用。旧第三方 fair/url_hash 配置不作为通用模板。

## 3. 配置时必须检查

| 项目 | 风险 |
| --- | --- |
| proxy_pass 路径与尾斜杠 | URI 转发规则改变 |
| Host / 转发头 | 错误目标或信任伪造头 |
| 超时与重试 | 重复副作用或长时间占用 |
| body 大小 | 内存、磁盘与滥用成本 |
| 缓存键与认证 | 私有数据错误共享 |
| TLS 与来源限制 | 明文传输或暴露内部服务 |

不要把 1024M body 上限当默认推荐。

## 4. 避免开放代理

旧文将任意 $host/$request_uri 转发的配置缺少目标与客户端限制，可能被滥用为开放代理或访问内部资源。本轮移除该可复制模板。代理应限制允许目标、调用者和网络范围；仅设置 resolver 不是安全防护。

## 5. 静态站点与变更流程

root/alias、MIME、缓存和路径遍历需要结合实际文件布局验证。修改配置后先做语法与目标检查，再按获准流程 reload；“不重启”也不意味着无影响。
