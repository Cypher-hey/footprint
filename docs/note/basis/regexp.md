# JavaScript 正则表达式：语法、状态与校验边界

> 审阅日期：2026-10-08。状态：JavaScript 语法范围纠错，示例未运行。
> 原笔记混入其他正则方言，本章以 JavaScript RegExp 为准。

## 1. 基础语法

| 语法 | 含义 |
| --- | --- |
| . | 默认不匹配行终止符；s 标志改变此行为 |
| \d / \D | ASCII 数字 / 非数字 |
| \w / \W | 常见模式下 ASCII 字母数字下划线 / 其补集；不是“含全部汉字” |
| \s / \S | 空白 / 非空白 |
| ^ / $ | 输入边界；m 模式涉及行边界 |
| [aeiou] | 任一列出的字符；不能随意加逗号 |
| * / + / ? | 零或多次 / 一或多次 / 零或一次 |
| (?:...) | 非捕获组 |
| (?<name>...) | 命名捕获组 |

问号作为数量词时不自动表示懒惰；放在量词后才改变其贪婪性。不同 flags 对匹配语义有影响。

## 2. 不同方言不能混用

JavaScript 不采用 (?'name'...) 命名组或 (?#comment) 注释组。捕获编号按左括号出现顺序，命名组也参与，不是先给未命名组编号再给命名组编号。

## 3. 字面量与构造函数

```js
const literal = /\d+/;
const constructed = new RegExp("\\d+");
```

字符串先经过 JavaScript 转义，再交给正则解析，所以反斜杠层数不同。动态用户文本不能直接拼接成正则而忽略转义与资源限制。

## 4. flags 与状态

g 全局、i 忽略大小写、m 多行、s dotAll、u Unicode 模式、y sticky，以及 d/v 等现代能力的支持范围需查目标环境。u 与 v 不是随意叠加。

带 g/y 的 test 和 exec 会涉及 lastIndex。复用同一个对象反复校验时可能得到交替结果，不能把它当作始终无状态的谓词。

## 5. 常用 API

exec 返回匹配信息或 null；test 返回布尔；match 在 g 与非 g 模式返回结构不同；matchAll 可遍历匹配及捕获；replace/replaceAll 的替换模板与函数回调语义不同。

## 6. 业务校验的边界

- Email 正则只做有限格式检查，不证明地址存在；不要把顶级域限制为 2–4 字母。
- 手机号、车牌等编号规则会变化，不把旧号段表当永久标准。
- 身份证或日期格式通过不代表真实性、合法日期或身份核验。
- URL 使用 URL 解析器后仍需限制协议、主机和目的地址；“能解析”不等于可以安全请求。
- 密码强度不能用“六位且四类字符”简单保证。
- 金额格式化可使用 Intl.NumberFormat；金额计算本身另需精度策略。

## 7. 性能和安全

嵌套量词与回溯可能被长输入放大，形成 ReDoS。对外部输入限制长度，设计反例和超时/隔离策略。复杂结构优先解析器，不用一个巨型正则解析任意 HTML。

## 8. 验证题

比较 /a/g 连续 test 同一字符串与 /a/ 的区别；解释 [a,e] 为什么还会匹配逗号；构造一条格式正确但并非真实存在的邮箱，说明校验边界。
