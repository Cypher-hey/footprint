# DOM 性能：批量更新、查询与生命周期

> 核查日期：2026-10-08。状态：历史建议重整；未采集新性能数据。

## 1. 成本模型

成本可能在查询、脚本计算、样式失效、布局、绘制、图层与内存。不是每次 DOM 写入都触发全页重排，也不是一次 append 就保证只做一次布局。

## 2. 有用的实践

- 缩小查询范围，避免反复寻找同一目标。
- 分离几何读取与写入，减少布局反复失效。
- 用 DocumentFragment 或离线结构组织更新可以改善代码，但速度收益需实测。
- 不随意 cloneNode 替换交互组件：监听器、焦点、选择区和内部状态可能丢失。
- 动画按时间推进，优先考虑 requestAnimationFrame 或合适的 CSS 动画，不以固定 10ms/50ms 作为通用策略。

## 3. Live 集合

边遍历 live 集合边改变成员可能跳项或不终止。可以先取快照或选择稳定迭代方式；静态 NodeList 与 live 集合要区分。

## 4. 历史经验修正

旧文的“table 慢三倍”“XPath 快两个数量级”“缓存节点快五到十倍”缺少现代复现环境，不应作为当前保证。querySelectorAll 可以表达常见的元素集合选择，没必要为所有查询引入 XPath。

## 5. 导航与释放

bfcache 可以恢复页面状态；不要以添加 unload 监听器作为默认恢复方案。使用合适的 pageshow/pagehide 等事件处理生命周期，并测试实际恢复。

AJAX 不天然破坏所有历史记录，可通过路由与 History API 设计导航。location.replace 改变历史条目语义，不是可靠的手动释放内存 API。

## 6. 安全与验证

不要用正则从任意 HTML 提取片段后直接 innerHTML 注入；避免 document.write 作为通用动态加载器。验证更新后焦点、监听清理、滚动位置和后退恢复。
