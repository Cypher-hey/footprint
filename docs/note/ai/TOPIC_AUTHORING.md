# AI 单主题作者规范：内容、模式与共享资源

> 内容基线：2026-10-10。用于本仓库的新主题作者源，不是通用 Knowledge IR，也不是 KnowledgeBlocks 协议升级。展示适配通过确定性构建展开共享图源，保留 Docute。

## 1. 三个层次

- **主题**回答一个相对完整的知识问题，拥有稳定 ID、标题、顶部摘要和主定义边界。
- **模式**提供同一主题的不同阅读目的，决定横向 Tab；不是把媒体类型互斥分区。
- **章节**组织当前模式的连续论述，决定纵向目录；图注应归属解释它的小节，不与主题章节混级。

单一作者源指每段内容及图源有确定维护位置，不指必须把全部内容塞进一个文件。概要是独立编写的浓缩解释，系统阐述拥有完整主定义，图解用另一条视觉主线解释关系。允许必要复述，禁止冲突定义与多份独立维护的同图源码。

## 2. 文件组织

```text
topics/
  index.json                    全体主题清单，显式顺序
  README.md                     人类阅读入口
  03-agent-loop/
    README.md                   主题入口与三个模式的链接
    topic.json                  主题身份、摘要、归属与旧路由
    modes/
      index.json                模式清单与默认模式
      overview.md               核心概要
      explanation.md            系统阐述
      diagrams.md               概念图解
    figures/
      index.json                图 ID、图源、图注、读图说明
      figure-01.mmd             唯一维护的 Mermaid 源
```

新模式简单时使用文件；复杂时使用文件夹，例如 `verification/index.md` 及 `verification/cases/`。清单必须明确入口，不按目录扫描结果推断顺序，不把每个文件都变成一个 Tab。当前没有创建空的代码验证模式。

## 3. 清单合同

`formatVersion: 1` 是本仓库作者包格式的整数标识，用于选择兼容解析路径，不声称遵循 SemVer，不沿用 KnowledgeBlocks 的版本兼容假设。字段语义改变或出现不兼容格式时须明确迁移，不能让旧读取器猜测新格式。

| 文件 | 字段 | 解释 |
| --- | --- | --- |
| topics/index.json | topics[].id / entry | 全局唯一 ID；entry 相对 topics/，指向 topic.json |
| topic.json | id / title / summary | 稳定身份、标题、固定顶部摘要 |
| topic.json | modes | 相对主题目录的模式清单路径 |
| topic.json | definitionScope | 本主题主定义与相邻主题分工 |
| topic.json | legacyRoutes | 从站点 hash 取出的兼容路由路径，不含站点域名 |
| topic.json | level / editedAt / contentStatus | 知识层级、内容编辑日期、交付状态；不代表实测成功 |
| modes/index.json | defaultMode | 必须指向存在的模式；当前采用 explanation |
| modes/index.json | modes[] | 数组顺序即显示顺序 |
| modes[] | id / label | 稳定机器标识与可修改的中文名称分开 |
| modes[] | entry | 相对模式清单所在目录的内容入口 |
| modes[] | renderer | 已登记的渲染类型；本轮均为 markdown |
| figures/index.json | figures[] | 图身份、源文件与读图说明；source 相对主题目录 |

不得把 JSON 字段解释为任意函数、命令或脚本。未知版本、未知 renderer、重复 ID、越界路径和缺失引用应报告具体文件与位置，不能静默猜测。

## 4. 三个模式怎样分工

### 核心概要

用连续短段落解释定义、关键机制与边界；随后提供易混点和主定义归属。读者应能快速恢复心智模型，不要求口语化，不设机械字数门槛。顶部 summary 更短，负责定位；overview 负责把主线说完整，两者不是重复列表。

### 系统阐述

保留动机、首次定义、最小完整机制、逐层展开、局部反例、条件、关联与来源。允许图、表、公式、代码和示意数据。事实和边界的主解释在这里维护。

每个模式一个一级标题；主章节从二级标题开始；图的标题按上下文降一级。当前部分图通过正文原位引用，没有必要额外制造一个同级大章节。

### 概念图解

先写读图主线，再按整体到局部、结构到时间的顺序安排图。每图回答一个明确问题，说明箭头和简化边界，并链接回系统阐述。不能只是把正文里的所有图片搬进图库，也不能用一张装饰图代替缺失的机制。

三个模式不应分别维护三套事实或引用体系；概要与图解通过链接回到完整解释和来源。

## 5. 共享图的可移植引用

采用标准 Markdown 链接及明确的 title 标记：

```markdown
[图 1：先看 Agent 与环境的反馈关系](../figures/figure-01.mmd "footprint:figure")
```

- 相对路径以当前 Markdown 文件为基准；图清单以主题目录为基准，二者不能混算。
- 普通 GitHub Markdown 会显示源文件链接，读者可查看 Mermaid 原文；它不会自动把外部 `.mmd` 链接渲染为图。
- 构建器识别 title 恰为 `footprint:figure` 的独立段落链接，校验受限的本主题图源，再在该位置显示图。
- 系统阐述与概念图解可以同时引用同一源文件。变更图只改源，避免两份源码漂移。
- 构建产物将已登记图源展开为 Mermaid 围栏，由浏览器的受限 Mermaid 渲染器原位显示；源码与文字说明保留。
- 失败时保留标题、源码/链接、文字说明；不显示一个看起来成功却缺失的空容器。
- 未来若构建生成 SVG、HTML 或展开后的 Markdown，它们都是派生资源，不成为第二套作者源，不由 AI 独立改写。

这只是局部图源引用约定，不引入完整自定义 DSL。标题和正文仍使用 Markdown。数学同时保留变量说明与普通文本表达，渲染支持必须实测。

## 6. 链接与定位

主题之间链接到相邻主题 README，深链接到其模式正文。规范、术语、知识地图、Advance 保持独立辅助页。源链接由发布适配器转换为站点路由，不能在作者正文里写死域名。

系统阐述使用显式 `section-01` 等章节锚点；首次上线后若重排章节，不应重新编号既有 ID。原 03 图的 `loop-control` 等语义锚点继续保留。编译阶段应检查重复锚点、失效目标和跨模式跳转，不依赖某个 Markdown 库的偶然 slug 行为。

新模式的锚点也需要稳定化；浏览器实际锚点及旧链接映射仍属于接入验收，不能因为源链接存在就判定已兼容。

## 7. 新增与修订流程

1. 确认已有主定义，决定补点还是新增主题。
2. 修改系统阐述，检查前提、来源、图文和反例。
3. 同步概要与图解受影响的结论，不要求逐字一致。
4. 检查共享图、主题/模式清单、相对链接和知识归属。
5. 用发布预览验证渲染、目录、切换和降级；未执行时明确标记。

参考写作原则继续遵循 [KNOWLEDGE_SPEC](KNOWLEDGE_SPEC.md)。实际项目实验可在别处进行；只有确有必要且已有证据时新增验证记录模式，包含条件、版本、观察、支持范围与未覆盖项。

## 8. 迁移期间的唯一编辑位置

本分支的 `topics/` 是下一版作者内容。根目录原编号 `.md` 暂留为旧站点兼容快照，未删除、未覆盖；不得同时独立修改两份。接入时应通过生成或路由映射让旧地址消费新源，并验证旧锚点。不要让读者把兼容快照和新作者源误认为两个持续演进的版本。

内容状态 `reviewed-content-pending-renderer` 只表示本轮内容整理与检查已完成，不表示外链全量核查、渲染通过、运行基准复现或知识永久正确。
