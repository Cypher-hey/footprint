# Evals 与可观测性：让改进成为可验证的判断

> 层级：核心工程。日期：2026-10-08。状态：评测方案，尚无实验数据。

## 1. 从演示转向证据

一次成功演示不能代表可靠性。评测需要明确任务集合、成功标准、环境、模型与配置，记录重复试验和失败类型。不要在看过所有失败后，仍把这组数据叫作独立测试集。

## 2. 指标分层

| 层 | 例子 | 易误读 |
| --- | --- | --- |
| 结构 | JSON/Schema 合格率 | 合法不代表事实正确 |
| 内容 | 准确性、引用支持度 | 文风好不代表正确 |
| 行动 | 工具选择、参数正确率 | 调用成功不代表任务完成 |
| 任务 | 最终产物符合要求 | 忽略越权副作用 |
| 体验与成本 | p50/p95 延迟、总费用 | 只看成功样本的平均值 |
| 安全 | 越权率、泄露、错误执行 | 正常集通过不代表对抗集通过 |

## 3. 构建小型评测集

为 AI Cards 建立基础集：概念卡、比较卡、代码卡、缺少证据、冲突资料、长文、非法 UI 结构、取消任务、旧请求回包和恶意输入。每条保存输入、允许资料、期望性质和禁止行为。

先写规则检查，再加人工复核；模型评审可以辅助，但应校准偏差、位置效应和与生成模型的相关错误。

## 4. 比较方案

保持任务、工具、数据和预算条件一致，一次只改变主要变量。比较模型时同时记录成功率、成本和耗时；比较 RAG 时检查检索质量；比较多 Agent 时计入协调成本。

小样本中一两条差异可能是偶然。报告样本数和重复次数，必要时使用置信区间，而不是只写“提升 20%”。

## 5. 轨迹记录

```json
{
  "taskId": "eval-07",
  "runId": "run-3",
  "step": 4,
  "event": "tool_completed",
  "tool": "read_document",
  "durationMs": 120,
  "status": "ok",
  "artifactRevision": "r2"
}
```

这是虚构示例。真实日志还需模型/提示词/工具版本、预算、停止原因与来源定位；不记录无必要的秘密或私人原文。

## 6. 错误归因

失败可能来自任务含糊、检索漏召回、上下文裁剪、模型判断、工具契约、环境故障或验收器错误。先归因，再决定改提示、工具或模型，避免所有问题都升级模型。

## 7. 回归与持续演进

把真实失败整理成去敏测试。开发集用于改进，保留集用于观察泛化；定期补新分布。上线前门禁不能只检查平均质量，还要检查高风险禁止行为。

## 8. 练习

比较两个生成模板，各跑同一组 20 条任务。先写评分规则，再看结果。列出“格式全对但结论错误”的例子，说明为什么单一通过率不够。

## 9. 一条可复用的用例

以下为虚构测试数据，来源段落与期望规则由测试作者提供，不让被测模型自己编造标准答案。

```json
{
  "caseId": "cache-no-store-01",
  "input": "根据资料生成一张说明 no-store 的概念卡",
  "sources": [
    {"id": "s1", "text": "no-store 指示缓存不要存储此请求或响应。"}
  ],
  "requiredProperties": ["解释不得存储", "引用 s1"],
  "forbiddenClaims": ["no-store 只是每次重新验证"],
  "forbiddenActions": ["publish", "execute_code"]
}
```

分层验收顺序：

1. Schema 检查：卡片类型、长度、字段与引用格式合法。
2. 来源检查：s1 确实存在；不能用模型生成的 URL 代替证据。
3. 语义检查：结论得到材料支持，且没有把 no-store 和 no-cache 混淆。
4. 行为检查：没有调用发布或任意代码执行工具。
5. 体验检查：引用可查看、错误可纠正；界面本身另测。

每条用例保存各层结果。高风险禁止行为可作为硬门禁，不用平均文字质量抵消越权。

## 10. 怎样解读一次 A/B

自写假设：同一组 20 题，A 对 15 题，B 对 17 题。只能先说观察到 75% 与 85%；这是增加 10 个百分点，不是“增加 10%”。相对增幅约 13.3%，但小样本不证明真实提升。

进一步保留逐题配对：哪些 A 对 B 错、A 错 B 对？重复采样、固定生成条件并说明波动。若新增两次成功同时发生一次越权，高风险场景不能仅按总正确率宣布胜出。

成本分母也要明确：每请求费用与每个成功任务费用不同。重试、失败、工具调用和并行分工的消耗都应计入完整任务成本。
