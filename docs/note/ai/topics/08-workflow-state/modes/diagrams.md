# Workflow、状态机与 XState：把行为边界写清楚｜概念图解

## 读图主线

Workflow 组织工作依赖，状态机限定有效转换；异步任务、取消与外部结果必须分层记录，才能解释恢复行为。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

<a id="figure-01"></a>

## 图 1：工作流中的一个模型决策节点

依赖图说明先后工作，不足以表达每个节点的异步生命周期。

[图 1：工作流中的一个模型决策节点](../figures/figure-01.mmd "footprint:figure")

图展示的是工作依赖，不足以说明节点内部是否正在执行、已取消或结果未知。要表达这些时间上的差异，就需要展开状态。

[结合正文解释阅读](explanation.md#figure-01)

<a id="figure-02"></a>

## 图 2：一个任务的生命周期

节点代表阶段，边代表事件；Succeeded 依赖被接受的结果，Cancelled 不证明远端无效果。

[图 2：一个任务的生命周期](../figures/figure-02.mmd "footprint:figure")

状态是节点，事件是边上的标签。成功依赖结果被接受与校验，不只是有一条消息返回；取消表示当前流程不再接收正常完成转换，不证明远端动作从未发生。

[结合正文解释阅读](explanation.md#figure-02)

<a id="figure-03"></a>

## 图 3：外部操作的结果确认状态

Unknown 表达认知不足；要通过核对进入已确认成功或失败，不能直接改名为失败。

[图 3：外部操作的结果确认状态](../figures/figure-03.mmd "footprint:figure")

图 2 表达任务生命周期，图 3 表达外部动作结果的确认状态。它们是两个层次：任务可以已经取消，某次外部操作的效果却仍需核对。把所有含义压进一个 loading 或 error 字段，会丢掉这种区别。

[结合正文解释阅读](explanation.md#figure-03)

## 图没有承诺什么

- Actor 不等于 Agent，也不等于线程。
- 保存快照不代表可以重新执行所有历史副作用。
- 取消本地任务与撤销外部动作是两件事。
