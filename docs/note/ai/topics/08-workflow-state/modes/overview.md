# Workflow、状态机与 XState：把行为边界写清楚｜核心概要

## 核心模型

Workflow 描述步骤、分支和交接；状态机描述当前状态在事件与条件下能怎样变化。二者可以配合，Agent 也可以作为工作流节点。是否需要状态机，取决于状态复杂度而不是是否使用 AI。

State 保存影响后续处理的情况，Event 表达输入或事实，Guard 检查转换条件。纯转换决定下一状态和需要安排的工作，外部请求结果作为事件返回；这样更容易识别旧响应并回放决策。

任务取消不代表远端效果被撤销，超时也不证明写入失败。运行状态与外部操作确认状态应分别理解。Actor 封装工作单元及生命周期，并不自动提供数据库事务；简单流程可从 reducer 开始，复杂层级与并行再评估 XState。

## 需要保留的边界

- Actor 不等于 Agent，也不等于线程。
- 保存快照不代表可以重新执行所有历史副作用。
- 取消本地任务与撤销外部动作是两件事。
