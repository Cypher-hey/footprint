# 工具、MCP 与 Skills：三种不同的能力边界｜核心概要

## 核心模型

Tool 是带输入、输出和副作用约定的能力接口；MCP 是宿主连接外部能力与上下文的协议；Skill 是可发现、按需读取的任务知识。工具可以不用 MCP，Skill 也不会因包含操作步骤就获得执行权限。

MCP 的 Host 管理应用与上下文，Client 维护具体 Server 连接，Server 暴露协议能力。工具、资源和提示模板用途不同；支持哪些能力依赖双方协商及版本。本文固定讨论 2025-06-18 的协议，不把它称为最新规范。

从模型调用到协议请求再到业务操作，标识和失败语义可能发生映射。能力协商说明支持什么，认证说明谁在请求，授权说明能访问什么，批准说明这次是否应执行。保持这些层次，才能定位接口问题而不误扩大权限。

## 需要保留的边界

- MCP Server 可以是本地进程，不必远程部署。
- JSON-RPC id 不能自动承担业务幂等。
- 工具名称、annotations 或 Skill 文本不是授权证据。
