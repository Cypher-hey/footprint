# 提示与模型行为：指令、示例、证据和不确定性｜概念图解

## 读图主线

提示改变当前求解条件，而非自动改变参数或权限；指令、示例、证据和状态各司其职，行为改进需要外部判据。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

## 图 1：在参数不变时改变条件

固定参数与本次上下文共同影响输出；输入中新增工具描述并不自动安装工具或授予权限。

[图 1：在参数不变时改变条件](../figures/figure-01.mmd "footprint:figure")

图的关键是两种输入各走一条线：参数决定已学得的映射，当前上下文决定此次求解条件。提示并没有凭空提供新工具，也不授予操作权限。

## 图 2：提示设计与外部核查形成反馈

回边应携带可定位检查结果，不能只把‘更认真’重复写回 Prompt。

[图 2：提示设计与外部核查形成反馈](../figures/figure-02.mmd "footprint:figure")

回边携带的是检查证据，不只是“请再认真一点”。如果检查仍完全依赖同一模型对自己的主观评价，反馈可能保留同一个错误。评测怎样建立独立性，在 [10 Evals](../../10-evaluation/README.md)展开。

[结合正文解释阅读](explanation.md#figure-02)

## 图没有承诺什么

- 角色扮演不能生成事实依据。
- XML 标签不是权限隔离机制。
- 同一模型再次赞同自己不构成独立证据。
