# AI 原生界面：Catalog、UI IR、Event IR 与可信执行｜概念图解

## 读图主线

Catalog 限定可表达能力，UI IR 描述结构，Renderer 映射界面；事件与副作用另有边界，扁平编码也仍需图校验。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

<a id="figure-01"></a>

## 图 1：模型描述内容，程序解释描述

在生成与界面之间找校验和渲染两层；候选数据并不直接执行任意组件代码。

[图 1：模型描述内容，程序解释描述](../figures/figure-01.mmd "footprint:figure")

这条链路把两个变化分开：模型可以在允许范围内组合内容，组件实现则由程序维护。生成失败时能在数据边界拒绝，而不必执行一段任意 JSX。代价是需要维护合同与实现之间的一致性。

[结合正文解释阅读](explanation.md#figure-01)

<a id="figure-02"></a>

## 图 2：一份关系，两种编码视角

实线表示父子关系，虚线表示 ID 寻址；改变编码方式不改变逻辑关系。

[图 2：一份关系，两种编码视角](../figures/figure-02.mmd "footprint:figure")

实线是逻辑父子关系，虚线是按 ID 查找节点。扁平化改变存放方式，没有让父子关系消失。下方 JSON 只用于说明这一个概念，不是完整应用协议。

[结合正文解释阅读](explanation.md#figure-02)

<a id="figure-03"></a>

## 图 3：界面反馈回路

跟随点击、领域事件、状态更新与视图回传；副作用不能由节点随意携带的函数名绕过控制。

[图 3：界面反馈回路](../figures/figure-03.mmd "footprint:figure")

事件描述“发生什么”；状态转换决定“允许下一步是什么”；effect 执行外部工作。把数据库写函数名直接塞进 UI 节点，会让表示层承担它不该拥有的执行权限。

[结合正文解释阅读](explanation.md#figure-03)

## 图没有承诺什么

- Flat 不代表无层级或天然无环。
- UI 按钮可见不能证明用户具有权限。
- 公开产品的界面相似不证明内部使用同一 IR。
