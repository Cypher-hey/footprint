# ReAct：推理与行动如何交替参与求解｜核心概要

## 核心模型

ReAct 将语言推理与环境行动交替组织起来。推理帮助识别信息缺口并调整计划，行动带回当前输入之外的观察；后续判断利用这些观察，才形成方法上的反馈。

Thought、Action、Observation 是经典轨迹中的概念角色，不是所有 API 都必须暴露的字段。可见推理文本不能视作模型全部内部机制，工具观察也可能错误、过期或不完整。

当路径取决于外部结果时，交替求解可能有价值；输入充分的简单任务可能不值得额外调用。具体收益要比较质量、延迟、成本与风险。Agent Loop 承载运行，Tool Calling 交接动作，授权与停止控制仍由程序落实。

## 需要保留的边界

- 写下三个标签不等于采用了有效 ReAct 方法。
- 工具反馈提供纠错机会，不消除幻觉。
- 不能把单次调用基线故意限制为没有证据的回答。

## 本主题负责解释什么

本主题维护 ReAct 的方法定义与和 CoT 的区别；不重复定义整个 Agent Runtime 或具体工具 API。
