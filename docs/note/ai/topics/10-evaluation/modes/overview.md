# Evals 与可观测性：让改进成为可验证的判断｜核心概要

## 核心模型

Evaluation 是在明确条件下判断系统性质，Benchmark 提供任务与比较规则，Metric 量化结果，Grader 应用评分准则。先界定要评价哪种能力，再决定用规则、人工还是模型评分。

应用评测既看内容，也看行动与最终产物：答案正确但越权执行依然是失败。开发样本用于改进，保留测试用于判断未见情况；读过失败并针对调整后，不能再把同一集合称为完全独立。

结果需要同时报告质量、风险、延迟、费用和不确定性。Trace 与必要日志把分数关联到上下文、调用、工具和校验阶段，帮助形成具体改进假设。LLM-as-judge 也有偏差，需要校准，不应把模型一致意见当作独立事实证明。

## 需要保留的边界

- 小样本的分数上升不证明普遍提升。
- 零次观察到越权不证明对所有攻击安全。
- 多次运行同一道题不是等量独立新任务。
