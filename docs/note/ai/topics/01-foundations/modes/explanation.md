## 1. 为什么需要先区分“模型”和“系统”

一个对话界面可以回答问题、读取文件、记住偏好，甚至修改外部资源。外观上都是“AI 做的”，内部却至少包含两类能力：模型根据输入产生输出，应用负责提供信息并处理输出。若不区分这两层，就很容易把保存历史解释成训练，把一句行动计划解释成动作已经完成。

**模型（Model）**在这里指一个具有特定计算结构与参数的输入输出映射。**应用系统（Application System）**则组织模型、数据、界面和外部操作，承担完整任务。模型能预测某个动作的描述，不等于它自行拥有对应的网络连接、账号和权限。

## 2. 领域、方法、模型与系统是不同分类轴

**人工智能（AI）**是研究和实现感知、学习、推理、规划、行动等能力的广泛领域。**机器学习（ML）**通过数据与目标获得可用于新输入的规律；**深度学习**主要使用多层神经网络学习表示和映射。AI 还包含搜索、符号推理、约束求解等方法，不只包含神经网络。

| 分类轴 | 它回答什么 | 典型对象 |
| --- | --- | --- |
| 问题与任务 | 要解决什么 | 语言理解、视觉、预测、规划 |
| 求解方法 | 怎样得到解 | 搜索、规则推理、统计学习、强化学习 |
| 模型结构 | 输入如何变成输出 | 线性模型、树、Transformer |
| 系统组织 | 能力怎样共同完成任务 | 检索问答、工作流、Agent |
| 部署与交互 | 怎样提供给使用者 | API、桌面应用、网页、设备 |

这些分类会交叉：视觉模型可以使用 Transformer；强化学习可以使用深度网络；Agent 可以由规则策略驱动，也可以使用语言模型做部分决策。LLM 与 Agent 因而不是同级替代品。

简单规则、传统模型和大模型也不是淘汰关系。结构化预测、精确计算、事务处理与开放语义生成具有不同约束，应按问题选择机制；“更新、更大、更自主”本身不构成适用性证明。

<a id="section-03"></a>

## 3. 打开黑箱：训练与使用有两条信息路径

**参数（Parameters）**是模型计算中可被训练调整的数值。**训练（Training）**依据样本和目标更新这些数值；**推理（Inference）**利用已有参数对当前输入执行计算。在普通应用调用中，推理通常不更新参数。

### 图 2：参数路径与当前输入路径

<a id="figure-02"></a>

[图 2：参数路径与当前输入路径](../figures/figure-02.mmd "footprint:figure")

向下的训练路径决定模型已学得的映射；右侧输入路径决定这一次计算能利用哪些材料。提供一份新文档后模型能回答其中内容，说明它利用了当前输入，不能单凭这个现象判定它已经训练过该文档。

| 信息放在哪里 | 通过什么改变行为 | 更新与纠错方式 |
| --- | --- | --- |
| 参数中 | 影响模型的输入输出映射 | 训练或适配，再评估与发布 |
| 当前上下文中 | 改变本次条件输入 | 修改请求，检查来源与预算 |
| 外部存储中 | 被读取后进入当前上下文 | 更新存储、索引、权限与版本 |

外部存储不是“模型直接看到的全部知识”。只有被读取、选入且未被裁掉的信息，才可能参与当前推理。三者可以组合，但生命周期不同。

## 4. 输出怎样成为系统结果

**运行时（Runtime）**在本知识库中指管理调用、状态、工具执行和停止条件的应用运行部分，详细机制由 [Agent Loop](../../03-agent-loop/README.md)负责。模型输出可能是文本、结构化数据，也可能是一个行动提议。

## 5. “知道”“推理”“正确”各自是什么意思

| 词语 | 应明确的含义 | 容易跨越的边界 |
| --- | --- | --- |
| 参数知识 | 模型通过训练形成的可用规律 | 不等于可逐条编辑的事实数据库 |
| 上下文知识 | 当前请求提供的信息 | 不等于未来请求一定继续可见 |
| Inference | 执行模型计算 | 不保证逻辑论证正确 |
| Reasoning | 分析、分解、演绎等求解行为 | 输出解释不等于内部计算的忠实日志 |
| 正确性 | 在指定任务、资料和条件下成立 | 流畅、自信或符合格式均不足以证明 |

“模型是概率性的”说明了某些建模与生成机制，不直接证明它不能完成复杂任务；“某次回答正确”也不证明它具备可靠的普遍能力。两类判断都需要明确条件和证据。

对生成事实、执行动作、保持权限这三件事，应分别提供来源检查、结果确认和运行时约束。这个区别是后续 [评测](../../10-evaluation/README.md)设计的基础。
