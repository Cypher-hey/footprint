# AI 应用全景：把模型、知识、控制与证据连接起来｜概念图解

## 读图主线

把 AI 应用放回信息、控制和证据三条主线：局部机制如何相连，比堆叠更多框架名称更能解释系统行为。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

<a id="figure-01"></a>

## 图 1：先看职责，不看框架

看职责之间的信息与反馈，不把图误读为固定五步流水线。

[图 1：先看职责，不看框架](../figures/figure-01.mmd "footprint:figure")

知识供给提供本次需要的信息，模型产生内容或决策提议，运行控制决定如何处理，交互呈现当前结果并接收新意图，验证对行为与产物给出证据。这不是五步固定流水线：验证可以出现在执行前、执行中和执行后。

[结合正文解释阅读](explanation.md#figure-01)

<a id="figure-02"></a>

## 图 2：把职责之间的输入输出展开

区分内容和行动两条处理路径；回边可能触发继续，也可能等待或停止。

[图 2：把职责之间的输入输出展开](../figures/figure-02.mmd "footprint:figure")

信息流描述“什么成为下一步输入”，控制流描述“下一步是否允许发生”。外部结果进入状态，不代表所有结果必须立即再次调用模型；运行时可能等待用户、核对未知操作或结束任务。

[结合正文解释阅读](explanation.md#figure-02)

<a id="figure-03"></a>

## 图 3：一份产物与三类相关记录

来源、产物、批准、操作与证据具有不同身份；不能用一个状态字段承载所有含义。

[图 3：一份产物与三类相关记录](../figures/figure-03.mmd "footprint:figure")

来源版本回答“依据哪份材料”，产物版本回答“修改了什么”，运行记录回答“怎样得到”，批准回答“允许什么”，操作结果回答“发生了什么”。同一个字符串不能自动兼任所有身份。

[结合正文解释阅读](explanation.md#figure-03)

## 图没有承诺什么

- 五视角不要求五个独立服务。
- 更自主不自动等于更先进或更适合。
- 一次项目成功只支持其观察范围内的结论。
