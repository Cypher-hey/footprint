# 多 Agent：分工收益、上下文成本与单一责任人｜概念图解

## 读图主线

多 Agent 将任务分给不同决策与信息边界；收益取决于依赖是否可分离，代价来自重复上下文、协调与结果合并。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

<a id="figure-01"></a>

## 图 1：从一个循环到多个决策边界

协调者可以是人、程序或模型；多个方框表示局部决策边界，不表示安全隔离。

[图 1：从一个循环到多个决策边界](../figures/figure-01.mmd "footprint:figure")

协调职责可以由程序、模型或人承担。图中的多个方框表达分工，不构成权限隔离；是否有独立工具权限和可见数据，需要额外的系统机制。

<a id="figure-02"></a>

## 图 2：把汇总前的依赖打开

先找分支之间是否真的独立，再看汇合等待；真实依赖必须补边，不能靠并发按钮消除。

[图 2：把汇总前的依赖打开](../figures/figure-02.mmd "footprint:figure")

三个子问题可并行，是因为所需输入能够独立提供；最终产物仍要等待它们的相关结果。若 B 实际必须先知道 A 的结论，图中就必须补上 A 到 B 的依赖，不能仅靠“开多个角色”获得并行。
