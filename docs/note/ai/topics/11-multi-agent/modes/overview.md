# 多 Agent：分工收益、上下文成本与单一责任人｜核心概要

## 核心模型

多 Agent 系统包含多个具有局部上下文或决策状态的单元。它们可以共享模型或进程，角色名称本身不会产生独立权限。划分时要明确目标、可见材料、允许工具和交付责任。

并行只缩短能够重叠的工作，串行依赖与共享资源仍决定关键路径。墙钟等待减少，不意味着总 token、费用或验证工作量减少。比较必须计入分派、交接、汇总和返工成本。

交接是一份有选择的信息投影，需要保存约束和来源。共享产物应有明确所有者与版本控制；相反结论回到证据裁决，不能靠多数票代替真伪判断。只有在相同质量门槛下出现收益，才有理由扩大分工。

## 需要保留的边界

- 增加角色数不必然缩短关键路径。
- 多个相似模型可能重复同一错误。
- 共享文件不代表共享完整且正确的上下文。
