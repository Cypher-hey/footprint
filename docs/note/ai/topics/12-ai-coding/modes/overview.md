# AI Coding 与 Harness：把交付变成受控闭环｜核心概要

## 核心模型

代码补全与完成仓库变更是不同任务。后者需要理解入口、依赖、状态归属和验收条件，再在受控范围内修改。Harness 指围绕模型的运行、工具、约束和验证设施，其边界应按项目说明。

清晰目录、契约、类型和测试让人和 AI 都更容易建立正确依赖模型；大量上下文不必然弥补入口错误。变更合同应给出目标、非目标、兼容条件、权限和检查依据，而不是逐行规定实现。

产物与证据必须绑定同一版本。类型、单元、集成、浏览器观察和审阅分别证明有限性质，不能互相冒充。项目经验写回知识库时，应提炼机制、条件与反例；一次修复通过不等于同类错误永久消失。

## 需要保留的边界

- 模型自述测试通过不是测试日志。
- 目录整齐不保证依赖与状态边界清晰。
- 测试之后又改代码，需要重新评估证据有效性。
