# 推理请求：输入、采样、结构化输出与流式传输｜概念图解

## 读图主线

一次推理请求跨越输入、计算、传输和应用处理；只有逐层恢复边界，才能区分可解析、可信与可执行。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

<a id="figure-01"></a>

## 图 1：先分清请求与业务结果

沿请求构造到应用处理阅读；工具提议出现在输出端，实际执行仍在应用控制之后。

[图 1：先分清请求与业务结果](../figures/figure-01.mmd "footprint:figure")

模型输出工具调用描述，不代表外部函数已经执行。模型输出合法 JSON，也不代表内容可信或操作已获授权。

[结合正文解释阅读](explanation.md#figure-01)

<a id="figure-02"></a>

## 图 2：把图 1 的“应用处理”展开

结构检查之后仍有领域、事实与动作边界；不要把校验画成一次万能判断。

[图 2：把图 1 的“应用处理”展开](../figures/figure-02.mmd "footprint:figure")

图中的终点分成展示与动作：合法对象可以用于内容处理，但对象里写着某个操作，仍只是一份待处理数据。动作许可由 [安全边界](../../09-reliability-security/README.md)定义。

[结合正文解释阅读](explanation.md#figure-02)

<a id="figure-03"></a>

## 图 3：逐层恢复边界

字节、字符、协议事件和业务对象是逐层恢复的边界，不存在每个网络块必然对应一张卡片的关系。

[图 3：逐层恢复边界](../figures/figure-03.mmd "footprint:figure")

箭头表示消费前一层、构造后一层，而不是每个块都产生一个对象。字符、事件和对象都可能跨越多次网络读取。

[结合正文解释阅读](explanation.md#figure-03)

## 图没有承诺什么

- 一个网络 chunk 不是一个完整 JSON。
- 合法 JSON 不等于真实结论。
- temperature=0 不构成跨服务版本的确定性承诺。
