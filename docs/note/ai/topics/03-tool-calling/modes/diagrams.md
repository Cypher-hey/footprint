# Tool Calling：模型提议怎样成为受控执行｜概念图解

## 读图主线

Tool Calling 用结构化数据交接行动提议；定义、提议、执行和结果是四类事实，关联正确也不等于操作获准。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

## 图 1：谁提出，谁批准，谁执行

关注 Model 与 Tool 之间的 Runtime 边界：可见能力不等于当前可执行权限。

[图 1：谁提出，谁批准，谁执行](../figures/figure-01.mmd "footprint:figure")

**读图结论：** 从模型输出到工具执行，中间有控制边界。工具可见不等于有权执行，格式通过不等于授权通过。

## 图 2：一次调用怎样完成往返

时间向下，调用标识贯穿提议与结果。最后一次模型调用必须能取得匹配结果；本图只展开正常往返。

[图 2：一次调用怎样完成往返](../figures/figure-02.mmd "footprint:figure")

**读图结论：** 时间向下，箭头表达交接，不代表每一步都成功。这是应用执行一个工具的正常路径；拒绝、取消和超时需要各自分支。结果被记下之后，还要进入模型输入。

[结合正文解释阅读](explanation.md#calling-roundtrip)

## 图没有承诺什么

- 模型产生调用描述，不代表函数已经执行。
- 多个工具请求不代表可以安全并行。
- 写入超时可能意味着结果未知，不能直接重试。
