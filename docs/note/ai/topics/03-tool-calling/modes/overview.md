# Tool Calling：模型提议怎样成为受控执行｜核心概要

## 核心模型

Tool Calling 将模型的行动选择表达为程序能解析的工具名与参数。应用提供能力描述，模型生成调用提议，运行时校验参数与权限，然后将提议分派到真实实现。托管工具也可能由服务提供方执行，执行责任要按合同区分。

结果要与原调用对应，并明确成功、失败、截断或未知状态。多个调用乱序返回时，关联标识比返回顺序可靠；调用 ID 解决配对，幂等键解决重复业务意图，二者不能直接互换。

执行结果经选择进入后续模型输入后，才能支持继续判断。该交接可单独发生，也可处在 Agent Loop 中；MCP 则可承担应用与工具服务之间的连接。结构输出约束不能代替业务授权与副作用核对。

## 需要保留的边界

- 模型产生调用描述，不代表函数已经执行。
- 多个工具请求不代表可以安全并行。
- 写入超时可能意味着结果未知，不能直接重试。

## 本主题负责解释什么

本主题维护工具定义、调用提议、结果关联和完整往返；工具发现与 MCP 归 05，写入恢复归 09。
