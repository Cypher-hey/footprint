# 深入模型层：后训练、蒸馏与推理系统｜概念图解

## 读图主线

模型适配改变参数或行为，推理系统改变计算安排；目标、参数化与运行优化属于不同轴，收益需同时看质量与资源。

先读整体边界，再打开内部职责或时间变化；图是简化机制模型，不是实际运行记录。所有图与系统阐述共享同一份源文件。

## 图 1：模型生命周期中的两个位置

按生命周期区分改变模型与运行模型；并非每个系统都必须经过所有阶段。

[图 1：模型生命周期中的两个位置](../figures/figure-01.mmd "footprint:figure")

并非所有模型都经过图中的每个阶段；图用于区分概念。改变 prompt 是改变请求条件，微调是改变参数，改调度是改变执行安排。三者可能改善同一个表面指标，但因果机制不同。

## 图 2：冻结主权重，在旁路学习增量

冻结 W，同时学习低秩 A、B；相加的是输出贡献，可训练参数减少不等于计算或显存按同一比例下降。

[图 2：冻结主权重，在旁路学习增量](../figures/figure-02.mmd "footprint:figure")

训练改变 A、B 而保持指定的 W 冻结。图是一层矩阵变换的简化视角；哪些层使用适配、是否合并权重以及缩放方式，都由具体实现决定。

<a id="figure-03"></a>

## 图 3：沿时间展开一次常见自回归请求

沿前缀与 KV 更新读生成循环；首 token 分布通常来自 prefill 末位置，图对后续生成作简化。

[图 3：沿时间展开一次常见自回归请求](../figures/figure-03.mmd "footprint:figure")

KV Cache 保存各层历史位置的 Key/Value 计算状态，使后续步骤不必重新计算完整前缀的 K/V。新 query 仍要访问相应历史；缓存减少重复计算，不表示长序列完全没有额外成本。第一枚新 token 的分布通常可由 prefill 末位置输出获得；图将后续逐步生成概括为 Decode，不表示首 token 一定还需额外完整处理一次输入。

[结合正文解释阅读](explanation.md#figure-03)

## 图没有承诺什么

- 减少某层可训练参数不等于整模型显存同比下降。
- KV Cache 不是应用长期记忆。
- 更低比特不保证所有硬件更快。
