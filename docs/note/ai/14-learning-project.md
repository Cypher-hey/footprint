# 贯穿实践：可验证的 AI 知识卡片助手

> 层级：综合实践。日期：2026-10-08。状态：练习计划，未创建应用、未调用付费 API。
> 目标：用一个有界项目贯通模型、上下文、工具、UI 与验证。

## 1. 任务定义

输入一份有权使用的技术材料，生成三张带来源的学习卡片。用户可查看原文、编辑、测试理解；所有发布动作先人工确认。

先用固定输入与模拟模型输出，避免在验证渲染和状态管理时同时调试模型不确定性。

## 2. 六个里程碑

| 阶段 | 产物 | 验收 |
| --- | --- | --- |
| 1. 固定卡片 | Catalog + Schema | 未知组件、超长文本被处理 |
| 2. 输入适配 | 文档到结构化卡片 | 每个引用定位到真实材料 |
| 3. 交互 | Event IR + reducer | 显示答案、重置、切卡正确 |
| 4. 受限 Agent | 检索、阅读、生成循环 | 步骤与预算上限有效 |
| 5. 审核流 | revision + 批准记录 | 旧批准不能发布新内容 |
| 6. 评测 | 固定任务集与报告 | 正常、失败、安全用例覆盖 |

不要求第一天引入向量库、状态机框架和多 Agent。先用实验揭示具体缺口。

## 3. 建议领域对象

Document、SourceExcerpt、CardDraft、CardRevision、Run、ToolObservation、Approval。它们分别管理内容、证据、生成状态和权限，避免把所有信息堆在 UI 节点属性中。

## 4. 十个最低测试

1. 完整有效输入。
2. 空文档。
3. 文档无相关答案。
4. 引用 ID 不存在。
5. 半截模型输出。
6. 未知组件与非法引用图。
7. 用户取消生成。
8. 旧请求晚到。
9. 重复发布事件。
10. 材料包含伪装指令。

## 5. 学习记录

每次实验记录假设、修改、结果、失败原因和下一步。区分“AI 做出来了”“我能解释”“我能换场景实现”。隔几天独立重做关键环节，而不是只重新阅读答案。

## 6. 进阶扩展

确实需要长文检索后添加 RAG；流程复杂后比较 reducer 与 XState；独立研究可并行后比较单 Agent 与多 Agent。每次升级带一组收益指标和撤回条件。

多模态、语音和 Computer Use 是动作与观察空间扩展，仍服从同一授权和反馈循环；不是默认开放任意外部操作。

## 7. 从失败中改进

把真实失败转成回归用例；先修检索、提示、工具或程序，再判断是否要改模型参数。让系统自己更新提示词或代码也需要评测、版本、审批和回滚，不应无门禁自我发布。

## 8. 完成标准

你能在白板上说明每一步数据从哪来、谁能改、哪些是可信证据、哪一层拒绝非法操作；演示失败路径也能恢复，并能拿出测试与来源记录。
