# Linux / Unix 命令速查：先区分读取和修改

> 审阅日期：2026-10-08。状态：文档审阅，命令未运行。
> GNU/Linux 与 macOS/BSD 的选项可能不同，使用目标系统的 man/--help。

## 1. 读取与定位

| 任务 | 示例 | 注意 |
| --- | --- | --- |
| 当前目录 | pwd | 修改前确认位置 |
| 列出文件 | ls -la | 隐藏文件也可能重要 |
| 看前十行 | head -n 10 file.txt | 文件必须是预期目标 |
| 看后五行并跟踪 | tail -n 5 -f app.log | 日志可能含敏感信息 |
| 搜索固定文本 | grep -nF 'text' file.txt | -F 与正则不同 |
| 查找文本文件 | find . -name '*.txt' | 引号防止 Shell 提前展开 |
| 查看磁盘空间 | df -h | 与目录大小 du 不同 |

## 2. 修改操作单独对待

cp/mv 可能覆盖，重定向 > 会截断文件，>> 追加，rm 通常不进桌面回收站。chmod、chown、服务停止、关机和时间设置会改变系统行为，不能和只读速查混成一键执行脚本。

不使用 chmod 777 作为默认权限修复，不把 rm -rf 全目录当作玩笑示例。先明确路径、影响范围、备份和恢复方式。

## 3. 文件与链接

touch 主要更新访问/修改时间，可创建不存在文件；不是任意设置所有元数据时间。硬链接与符号链接不同，后者可指向相对路径。glob 匹配和正则表达式也是不同机制。

## 4. find 时间条件

-mmin -30 表达小于 30 分钟的时间范围；+30 不是“半小时内”。-size +1M 与 -1M 的方向相反，单位和取整规则要看实现，不能只按自然语言猜。

## 5. 文本处理

```sh
grep '^o' test.log
grep 'K$' test.log
cat -s test.log
tail -n 5 -f test.log
```

分别示范行首、行尾、压缩重复空行和日志跟踪。echo 本身输出文本，写文件来自重定向机制。把管道结果写回输入文件可能先截断原文件，需使用安全的临时文件流程。

## 6. 压缩与解压

打包和压缩是不同步骤。解压前查看内容和目标路径，警惕覆盖、路径穿越及超大文件。不要在系统根目录直接展开陌生归档。

## 7. 练习

给一组命令标记“只读、写文件、改权限、终止进程、网络传输”。解释为什么 Permission denied 不是自动 sudo 的理由，为什么 grep 进程列表会把 grep 自己也匹配进去。
