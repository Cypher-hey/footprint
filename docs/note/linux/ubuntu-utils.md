# Ubuntu 运维旧记：版本边界与安全排查

> 原笔记背景：Ubuntu 14.04、Node 5 等历史环境。
> 审阅日期：2026-10-08。状态：风险纠错；未执行系统操作。

## 1. 软件安装

旧版本号、PPA 与安装包路径只说明当时环境，不是当前安装建议。先确认发行版支持周期、目标软件维护版本与官方安装方式，再决定系统包或用户级版本管理。

不因“系统仓库版本较旧”就自动添加第三方源，也不默认复制二进制到系统目录。

## 2. Shell 差异

脚本需要 Bash 特性时，使用明确 shebang 或显式 Bash 执行；POSIX sh 脚本用兼容语法。不要为了一个脚本的 source 命令改变整个系统的 /bin/sh 指向。POSIX 中点命令 . 可读取脚本，但也会执行其内容。

## 3. 数据库无法启动

先查日志、端口、磁盘、权限、进程和版本兼容。旧文直接删除 lock/socket 文件不是通用修复，数据库恢复操作可能影响数据。必须确认没有存活实例，并按对应版本的官方恢复流程处理。

## 4. 用户与 sudo

最小权限优先。sudoers 应使用具备语法校验的受支持方式编辑，不能先 chmod 放开权限再随意修改。用户名与 %组名不同；不要把所有用户都赋予无限管理能力。

## 5. 进程管理

nohup 可改变挂断信号相关行为，不等于开机自启、故障重启、日志轮转或完整服务管理。长期服务应明确监督机制与生命周期。

终止进程前核对 PID、命令、所有者和影响。先考虑优雅停止；SIGKILL 无法让进程清理资源，不作为默认首选。

## 6. 编码与环境

乱码先检查终端编码、locale 可用性、文件编码和程序配置，不以全局改语言并重启作为唯一方案。

## 7. 练习

为“服务启动失败”写一份只读排查清单；在决定重启、修权限或删文件前分别说明需要哪些证据和备份。本文保留历史学习价值，不提供未经确认的生产修复捷径。
