## git 常用命令及技巧

#### 查看 ssh 公钥方法

###### 通过命令窗口

a.打开你的 git bash 窗口

b.进入.ssh 目录：cd ~/.ssh

c.找到 id_rsa.pub 文件：ls

d.查看公钥：cat id_rsa.pub 或者 vim id_rsa.pub

###### 直接输入命令

cat ~/.ssh/id_rsa.pub

###### .ssh 文件夹

#### 何谓公钥

1.很多服务器都是需要认证的，ssh 认证是其中的一种。在客户端生成公钥，把生成的公钥添加到服务器，你以后连接服务器就不用每次都输入用户名和密码了。

2.很多 git 服务器都是用 ssh 认证方式，你需要把你生成的公钥发送给代码仓库管理员，让他给你添加到服务器上，你就可以通过 ssh 在服务器授予的仓库权限内访问了。

#### 生成公钥：

1.如果通过上面的方式找不到公钥，你就需要先生成公钥了：ssh-keygen

`ssh-keygen -t rsa -C "youremail@example.com"`

2.接着会确认存放公钥的地址，默认就是上面说的路径，直接 enter 键确认

3.接着会要求输入密码和确认密码，是否设置密钥口令应按安全需求决定，不默认推荐无口令。生成前确认不会覆盖现有密钥

#### git merge --no-ff

能够 fast-forward 的条件是当前提交为目标提交的祖先，而非仅仅“没有冲突”；是否使用快进还受选项与配置影响，所谓 `fast-forward` 指的是：不产生新的提交历史，直接移动 `HEAD` 至要合并的分支，显而易见的缺点是合并历史信息不清晰，如下图(一条线)：

<img src="../../asset/img/git-merge.png" width="200" />

所以为了显式保留合并节点与分支合流结构，我们可以采用 `--no-ff` 选项，这样合并后的历史记录图类似于这样：

<img src="../../asset/img/git-merge-noff.png" width="200" />

#### git merge --squash

--squash 把合并结果准备到工作区与暂存区，不自动创建合并提交；后续普通提交也不会保存相同的双父合并关系，效果类似下图：
