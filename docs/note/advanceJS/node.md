# 中间件：职责链、横切逻辑与异步顺序

> 审阅日期：2026-10-08。状态：概念扩展，未运行框架示例。

## 1. 角色

中间件把日志、鉴权、解析、业务处理和错误处理组合成请求管道。AOP 是更广泛的横切关注点思想；中间件不是 AOP 的唯一实现，也不保证天然低耦合。

## 2. 顺序是合同

鉴权前后的数据可信度不同；错误边界是否覆盖下游、响应是否已经发送、next 是否可重复调用，都取决于框架。Express 的 next 风格与 Koa 的 await next 洋葱模型不能混为一谈。

## 3. 最小教学流程

```text
记录请求开始
  → 验证身份
  → 解析并校验输入
  → 处理业务
  → 形成响应
记录耗时并清理资源
```

失败也要进入错误记录与清理，不能只记录成功请求。

## 4. 工程边界

不要在中间件里偷偷修改无关全局状态。每层输入输出、可变字段和副作用应明确；异步处理需要传播取消、超时和错误。

## 5. 练习

设计两个中间件，一个计时、一个可能失败。写出成功、异常和重复调用 next 时的预期顺序，再按实际框架文档核查。
